# Установка UniFi Network на riscv64

**Неофициальный экспериментальный установщик.** `v0.2.0` добавляет нативный WebRTC
для удалённого доступа; используются стабильные UniFi Network и MongoDB. Проект не
поддерживается Ubiquiti или MongoDB как официальная сборка.

## Что поддерживается

- Debian **13 Trixie riscv64**, в том числе Armbian на базе Debian 13.
- Работающий **systemd**.
- RV64GC, little-endian, ABI **LP64D**, расширения Zicsr/Zifencei.
- glibc ≥ 2.38, GLIBCXX ≥ 3.4.32, CXXABI ≥ 1.3.15; OpenSSL 3 и libcurl с OpenSSL.
- Нативный OpenJDK **25** из настроенных репозиториев Debian.
- Рекомендуется от **2 ГиБ ОЗУ**, минимум **3 ГиБ свободного места** для установки
  и отдельный запас места для базы и резервных копий.

Аппаратно проверен **Orange Pi RV2 / SpacemiT** с Debian 13-based Armbian.
Другие соответствующие этим требованиям платы — кандидаты, а не подтверждённые
модели. Ubuntu, Debian 12, Alpine/musl, другие ABI и эмуляция архитектуры не
поддерживаются этим релизом. Требования взяты из фактических ELF-бинарников:
[подробности](COMPATIBILITY.md).

Интернет, DNS, IP-адрес и доступ к нужным портам должны работать до установки.
Скрипт не меняет адреса, маршруты, Wi-Fi и настройки firewall.

## Одна команда

На поддерживаемой системе с `curl` и `sudo`:

```sh
curl -fsSL https://github.com/ultrapravyj/unifi-riscv/releases/download/v0.2.0/install.sh | sudo bash
```

По желанию укажите адрес, который контроллер сообщает устройствам:

```sh
curl -fsSL https://github.com/ultrapravyj/unifi-riscv/releases/download/v0.2.0/install.sh | sudo bash -s -- --host АДРЕС_КОНТРОЛЛЕРА
```

Обычная установка **ничего нативного не компилирует**: готовые MongoDB и JNI
скачиваются из Release с проверкой SHA256. Официальный UniFi скачивается напрямую
у Ubiquiti, тоже с проверкой опубликованной контрольной суммы. Java и системные
библиотеки ставятся из Debian.

Проверенный набор: **UniFi 10.6.106 / build 36011**, **MongoDB 7.0.43**,
**notify JNI v0.1.0**, **WebRTC JNI v0.2.0 / libdatachannel 0.23.2**, **OpenJDK 25**. Конкретные обновления безопасности Java/библиотек
следуют репозиториям Debian; архивы приложения и компонентов зафиксированы хешами.

## Открыть контроллер

В конце установки выводится адрес **https://АДРЕС_КОНТРОЛЛЕРА:8443/**.
Первоначальный сертификат self-signed. Дождитесь завершения запуска Java,
откройте страницу и завершите мастер первоначальной настройки.

Службы:

```sh
systemctl status unifi-riscv mongod-riscv --no-pager
```

MongoDB слушает только `127.0.0.1:27017`, с индивидуальными случайными учётными
данными. Пароли не выводятся. Готовность контроллера — это `meta.up=true`
в `/status`, а не только наличие процесса Java. systemd получает реальный
`READY=1` через нативную JNI-библиотеку.

## Повторный запуск и существующая установка

Повторный запуск управляемой этим установщиком установки проверяет службы,
базу и контроллер и сохраняет настройки, данные и учётные данные. Прерванная
установка продолжается по сохранённому состоянию.

Для существующей установки проекта, включая старую структуру без `state.json`,
доступно точечное восстановление облачного транспорта без замены базы и настроек:

```sh
curl -fsSL https://github.com/ultrapravyj/unifi-riscv/releases/download/v0.2.0/install.sh | sudo bash -s -- --repair-cloud
sudo python3 /opt/unifi-riscv/scripts/cloud.py check
sudo python3 /opt/unifi-riscv/scripts/cloud.py probe
```

После этого проверьте открытие панели и раздела Networks через **unifi.ui.com**.
[Причина и проверка исправления](CLOUD-ACCESS.md), [совместимость старой структуры](MIGRATION.md).
Создавать фиктивный state-файл или удалять рабочую базу не требуется.

## Обновление, резервная копия и возврат

```sh
sudo python3 /opt/unifi-riscv/scripts/manage.py status
sudo python3 /opt/unifi-riscv/scripts/manage.py backup
sudo python3 /opt/unifi-riscv/scripts/manage.py update
sudo python3 /opt/unifi-riscv/scripts/manage.py rollback
```

Обновление выбирает официальный stable-релиз UniFi, проверяет сумму и совместимость
Java/MongoDB/JNI, заранее скачивает приложение, создаёт cold backup, переключает
версию и проверяет реальную готовность. При ошибке запуска автоматически
возвращает прошлые приложение, базу и конфигурацию. Готовая JNI используется
повторно; обновление не требует компиляции MongoDB или пересборки машины.

```sh
sudo python3 /opt/unifi-riscv/scripts/manage.py update --version 10.6.106 --reinstall
sudo python3 /opt/unifi-riscv/scripts/manage.py rollback --archive /opt/unifi-riscv/backups/КОПИЯ.tar.gz
```

При изменении требований Java/JNI/базы обновление останавливается для проверки
совместимости. Старые каталоги приложения и вытесненные при откате данные сохраняются.

Cold backup содержит рабочую базу и секретную конфигурацию, поэтому это **личный
архив**, а не файл для GitHub Release. Сохраняйте приватно `.tar.gz` вместе с
соседним `.tar.json`, содержащим сумму и сведения о предыдущем приложении.

## Пути и диагностика

| Что | Где |
|---|---|
| Приложение / активная версия | `/opt/unifi-riscv/app/`, `app/current` |
| MongoDB / компоненты | `/opt/unifi-riscv/mongodb/`, `components/` |
| Данные UniFi | `/var/lib/unifi/` |
| Данные MongoDB | `/var/lib/unifi-mongodb/` |
| Приватная конфигурация | `/etc/unifi-riscv/` |
| Логи | `/var/log/unifi/`, `/var/log/unifi-mongodb/` |
| Cold backup | `/opt/unifi-riscv/backups/` |

```sh
journalctl -u unifi-riscv -u mongod-riscv --no-pager
curl -kfsS https://127.0.0.1:8443/status
ss -lntup
free -h
```

Основные порты: TCP **8443** и **8080**, UDP **3478** и **10001**.
Также приложение может слушать TCP 8880, 8843, 6789, 28082 и UDP 5514.
Firewall автоматически не включается и существующий SSH не перенастраивается.

## Что проверено и ограничения

[Отчёт проверок](VALIDATION.md) отдельно описывает исходный работающий контроллер,
новый установщик в чистом нативном Debian/systemd-контейнере и ещё не проверенные
сценарии на отдельной bare-metal ОС. Проверки старой установки нельзя выдавать
за подтверждение нового установщика.

- В MongoDB отсутствует **server-side JavaScript**: недоступны `$where`, JavaScript
  `$function` и старые map-reduce/eval. Проверенные запуск, база и UI UniFi работают;
  требования следующих релизов следует проверять.
- **Adoption физической точки доступа не проверялся.** Тест ответа inform/STUN
  не равен успешному подключению настоящего AP.
- Standalone UniFi 10.6 пишет повторы обращения к отсутствующему UniFi OS
  ULP/SSL-inspection на `127.0.0.1:9080/api/ucore/manifest`. Компоненты UniFi OS
  этим установщиком не предоставляются; это не цикл перезапуска контроллера.
- MongoDB использует опубликованный TLS-адаптер сборки. Выполнение всех компонентов
  остаётся нативным riscv64; эмуляции CPU нет.

## Исходники и лицензии

MongoDB распространяется по **SSPL-1.0**, не по MIT. Полные соответствующие исходники,
пять патчей, инструкции и notices приложены к тому же Release, что и бинарник.
Сам установщик и собственная JNI-обёртка — MIT. Проприетарный UniFi не перепаковывается
в наш Release. Java и системные библиотеки устанавливаются из Debian.
Подробности: [THIRD-PARTY.md](../THIRD-PARTY.md), [сборка из исходников](BUILD.md).
